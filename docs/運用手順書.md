# 運用手順書：備品所在管理システム

## 1. 全体像
備品に貼ったNFCタグにiPhoneをかざすと、その瞬間のGPS位置が記録されます。備品検索から、最後の記録の方向と距離を示す**レーダー**で探せます。

- **位置の精度**：屋内の実測で、誤差は約15〜17mです。「このセンター内のどのあたり」までが目安で、部屋や棚は特定できません（2026-11-16、太田開発センター2Fでの実測）。
- 画面にも、「おおよその位置」「誤差」を表示します。

## 2. 最初のセットアップ（管理者）

### 2.1 最初の管理者を作る
Azure の DB に、このPCから直接つないで作成します（パスワードは、ご自身で入力します）。
```powershell
cd c:\works\tanaoroshi
foreach ($n in "DB_SERVER","DB_NAME","DB_USER","DB_PASSWORD") {
  $v = az webapp config appsettings list -g rg-tanaoroshi -n rs-mobi-tana --query "[?name=='$n'].value | [0]" -o tsv
  Set-Item -Path "Env:$n" -Value $v
}
$env:DB_TRUSTED = "false"
.venv\Scripts\python.exe -m app.cli create-admin <ログインID> "<表示名>"
Remove-Item Env:DB_SERVER, Env:DB_NAME, Env:DB_USER, Env:DB_PASSWORD, Env:DB_TRUSTED
```

### 2.2 ユーザーを追加する
管理者でログイン → 上部の「ユーザー」→ ログインID・表示名・権限を入力して追加します。
- **初期パスワードは自動で発行され、その画面に一度だけ表示されます**。本人に安全な方法で伝えてください。
- 本人は、初回ログイン時にパスワードを変更します（12文字以上）。
- パスワードを忘れたときは、「PW初期化」で再発行します。
- 端末を紛失したときは、「無効にする」で、ログインを止めます。
- ログインに5回失敗すると、15分間ロックされます（自動で解除されます）。

### 2.3 備品を登録する
- 1件ずつ：「備品」→ 管理番号（半角数字10桁）・名称・種別を入力して登録します。
- まとめて：「備品」→「CSV取込」。1行目に見出し（`管理番号,名称,種別,備考`）を書いたCSVを選びます。
  - 文字コードは、UTF-8 か Shift_JIS です。
  - **Excelで、管理番号の先頭の0が消える**ときは、列の書式を「文字列」にしてください。
  - **1件でも誤りがあると、何も登録されません**。表示された行を直して、もう一度取り込みます。
  - 登録済みの管理番号は、飛ばされます（同じファイルを何度取り込んでも安全です）。
- 種別は、「種別」の画面で追加・停止できます。

## 3. NFCタグの書き込み

### 3.1 書き込むURLの確認
「備品」→ 対象の備品を開く →「NFCタグに書き込むURL」を使います。
```
https://<ホスト名>/i/<ランダムな12文字>
```
- **URLに、管理番号は含まれません**。
- 現在のホスト名は長いため、URLは約77バイトです。**NTAG215（504バイト）なら書き込めます。NTAG210（48バイト）には、書き込めません。**

### 3.2 書き込み（iPhone、市販アプリ）
1. App Store の NFC 書き込みアプリ（例：NFC Tools）を開きます。
2. 「書き込み」→「レコードを追加」→「URL」→ URLを貼り付けます。
3. タグにiPhoneをかざして書き込みます。
4. **書き込み後に、そのタグを読み取って、備品の画面が開くことを確認します**。
5. 備品に貼ります（金属面に貼る場合は、金属対応のタグを使います）。

### 3.3 ロックについて（重要）
**ドメインが確定するまで、タグをロックしないでください。** ロックは元に戻せません。ホスト名を変えると、書き込み済みのタグは使えなくなります。

### 3.4 タグのURLを作り直す（紛失・流出したとき）
備品の画面で「URLを再発行」します。**以前のタグは、使えなくなります**。新しいURLを、タグに書き込み直します。

## 4. 日常の使い方（利用者）

### 4.1 所在を記録する
1. 備品のタグに、iPhoneをかざします。
2. 通知をタップします（Safariが開きます）。
3. 初回は、**ログイン**と、**位置情報の許可**が必要です。位置情報は、「許可」にしてください。
4. 「所在を記録しました」と表示されれば、完了です。

位置情報が許可されていないときは、位置なしで「確認」だけが記録されます。次を確認してください。
- 設定 → プライバシーとセキュリティ → 位置情報サービス → オン
- 同じ画面の「Safari Webサイト」→「次回確認」または「Webサイトの使用中のみ許可」
- Safari のアドレスバー左の「ぁあ」→「Webサイトの設定」→「位置情報」→「許可」

### 4.2 備品を探す（レーダー）
1. 「検索」で、名称か管理番号を入力して、備品を選びます。
2. 「この備品を探す（レーダー）」をタップします。
3. 「コンパスを使う」を押すと、スマホの向きに合わせて表示されます（初回に許可が必要です）。
4. **距離が誤差の範囲内なら、「近くにいます」と表示され、方向は示されません**。周りを探してください。

レーダーの間だけ、スマホの位置を連続で取得しますが、**この端末の中で計算するだけで、サーバーには送られず、保存もされません**。

### 4.3 要確認リスト
次の備品が表示されます。
- 90日以上、確認（タグへのタッチ）がない備品
- 位置の記録がない備品
- 建物の外にある可能性のある備品（フロア図の位置合わせがあるときのみ）

### 4.4 棚卸
対象の備品のタグを、順にタッチします。位置と「最後の確認」が更新されます。タッチされなかった備品は、一定期間後に、要確認リストに出ます。

## 5. 管理作業
| 作業 | 方法 |
|---|---|
| 備品の編集 | 「備品」→ 対象を開く |
| 廃棄 | 備品の画面で「廃棄する」。台帳・検索から消え、履歴は残ります（「廃棄済みも表示」で確認、取り消しも可） |
| 台帳のCSV出力 | 「備品」→「台帳をCSV出力」（管理番号・名称・種別・最後の位置・タグURL） |
| 位置履歴のCSV出力 | 「備品」→「位置履歴をCSV出力」 |
| フロア図 | 「フロア図」で追加。位置合わせ（左上・右下の緯度経度）を登録できます（現在、利用者向けの画面では使いません） |

## 6. デプロイ（コードの反映）
1. ローカルでテストを実行します。
   ```powershell
   .venv\Scripts\python.exe -m pytest -q
   ```
2. ZIPを作成します（`.env`、`.venv`、`tests` は含めません）。
   ```powershell
   .venv\Scripts\python.exe -c "import zipfile,pathlib;z=zipfile.ZipFile(r'C:\works\deploy.zip','w',zipfile.ZIP_DEFLATED);z.write('requirements.txt');[z.write(p,p.as_posix()) for p in pathlib.Path('app').rglob('*') if p.is_file() and '__pycache__' not in p.parts]"
   ```
3. Azure ポータルで、Web App → 開発ツール → 高度なツール → 移動 → `/ZipDeployUI` に、ZIPをドラッグ＆ドロップします。
4. ビルドと再起動で、約5分かかります。完了後、`/health` が `{"status":"ok"}` を返すことを確認します。

注意：
- **テーブルを変更したとき**（列の追加など）、現在は起動時の自動作成（`create_all`）のため、**既存のテーブルは変更されません**。変更が必要な場合は、先に、データのバックアップとテーブルの再作成を検討します（Alembic の導入は、今後の課題です）。
- SCM基本認証を、デプロイのために一時的にオンにした場合は、**終わったらオフに戻します**。

## 7. バックアップ・ログ・費用
- **DB**：Azure SQL の標準のバックアップ（自動）。復元は、ポータルの SQL データベース →「復元」から、新しいDBとして行います。
- **ログ**：`az webapp log tail -g rg-tanaoroshi -n rs-mobi-tana`、またはポータルの「ログストリーム」。
- **費用**：月額約$19（約2,900円、税別）。App Service B1 が約$14、SQL Basic が約$5.5、ストレージは数円です。停止しても課金は続きます。PoC終了後は、リソース グループごと削除すると、課金が止まります（**削除前に、必要なデータをCSVで出力してください**）。

## 8. 既知の制約・今後の課題
- GPSだけでは、部屋・棚は特定できません（誤差約15〜17m）。
- ホスト名が長い（約61文字）。**NTAG210には書き込めません**。本番化では、短いカスタムドメインを推奨します。
- SQLのファイアウォールが、「Azure サービスを許可」で広い。本番化までに、絞ります。
- ストレージは、暫定でキーを使用。マネージドIDのロール付与後に切り替えます。
- `/test/geo`（位置情報テスト）は、ログインなしで書き込めます。**測定が終わったら、停止または削除してください**。
- Alembic（マイグレーション）は、未導入です。
- 他の建物（2フロア）での、位置情報の実測が未実施です。
